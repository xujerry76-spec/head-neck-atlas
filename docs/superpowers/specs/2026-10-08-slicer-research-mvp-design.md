# Slicer 头颈 CT 科研 MVP 设计

日期：2026-10-08
状态：技术路线已获用户批准；本设计待审阅。

## 目标与边界

用户希望参考领英示例，浏览自己的 CT 病例，自动分割解剖结构，随切片显示可调整的解剖标签，并保存科研结果。采用本地 Windows 桌面、单用户、单病例工作流。第一版限定头颈 CT，不训练模型。

使用已发布稳定版 3D Slicer、SlicerTotalSegmentator 扩展及其兼容的 TotalSegmentator。实现前锁定并记录实际通过验证的版本，不使用预发布权重。现有项目负责 DICOM、渲染、分割和编辑，新建 Python scripted module 负责科研工作流与标签。

## 用户工作流

1. 使用 Slicer DICOM 模块导入病例，在新模块中选择 CT 输入体积；拒绝非 CT 或无有效几何信息的输入。
2. 默认显示轴位，可切换 Slicer 已有三平面布局；复用滚动、窗宽窗位、缩放和平移。
3. 选择头颈分割任务，调用现有扩展。第一版提供 head_glands_cavities 和 head_muscles 两项，分别运行；不假定它们支持快速模式或 ROI 子集。
4. 从任务输出中显示首批六类结构：左右眼球、左右腮腺、左右咬肌。其他输出保留但默认隐藏。任务类别在运行前检查，不支持时给出明确原因。
5. 按结构查看轮廓、名称、显示开关并跳转到代表切片。复制自动分割为独立修正分割后，在 Segment Editor 中修改。
6. 保存研究包并重新打开。计算和导出各结构体积，保留自动与人工修正两份结果。

## 模块职责

- 工作流面板：选择输入、选择任务、启动运行、显示状态、结构列表、保存和加载。
- 推理适配器：检查扩展与模型可用性，调用扩展现有逻辑；在子进程执行重计算，保持界面响应，捕获错误。若已锁定版本只能同步调用，先解决异步适配再验收。
- 标签控制器：监听轴位切片及分割变化，计算结构在当前平面上的截面和锚点，更新覆盖层，不执行推理。
- 研究包读写：保存 Slicer 场景及影像、两份分割、标签显示设置、元数据和 CSV，校验文件完整性。

使用 Slicer 的 MRML 节点与事件连接这些模块，禁止按文件名顺序自行拼接 DICOM。保持既有 Slicer 安装及上游源码完整，通过独立扩展加载。

## 标签行为

采用当前切片上最大连通区域的内部点作为引线锚点，按患者坐标通过 Slicer 变换映射到屏幕。结构在当前切片不存在时隐藏，不在别的切片复制固定位置。

标签显示于视图两侧，先按锚点纵向排序，以固定最小间距避让。第一版保证六类结构范围内标签可读，不承诺任意类别数量下完全无重叠。

拖动文字框只修改标签显示偏移并保存；解剖锚点来自分割，不允许拖动文字框改变解剖边界。切片变化重新计算锚点，保留每个结构的文字框偏移。空间不足时收起部分文字框，保留结构列表和轮廓。中英文名称来自明确的类别映射。

## 数据与科研记录

研究包目录使用用户指定的研究编号。保存 scene.mrb（包含体积与分割）、labels.json、run.json、volumes.csv，以及供外部分析的影像 NIfTI 与自动/修正多标签 NIfTI 文件、类别映射表。保存完成前校验各文件可以读取，原子替换清单避免把未完成包标为成功。

run.json 记录输入几何、序列标识、任务名称、Slicer/扩展/模型包版本、可获得的权重标识、设备、实际参数、时间和耗时。无法获得的信息明确标为 unavailable，不能编造。自动结果只读留存，人工修正操作在复制节点上执行。

体积按分割几何的体素体积计算，单位 mL；不存在的结构标为 absent，不混同运行失败。影像导出保留实际方向、间距和原点，须验证与分割对齐。

本地处理病例；首次安装或首次运行可能下载依赖和权重。导入操作不等于脱敏，研究包可能仍含 DICOM 标识或场景属性，分享前需独立检查。

## 错误与运行环境

- 缺扩展/依赖/权重：显示具体缺失项和安装路径，不自动静默下载。
- GPU 不可用：允许明确选择 CPU，显示可能较慢；显存不足时保留失败信息，允许用户改用 CPU 重试。
- 推理失败：保留输入和此前结果，不写入成功记录。
- 几何不匹配：阻止错误叠加或导出，只有经过明确参考几何重采样和验证才能继续。
- 标签观察者在切换病例、关闭场景时清理，避免旧标签残留。

当前工作区为空，仅有未提交的 Git 仓库。常见安装位置未发现 Slicer；不能据此断言机器上未安装。硬件查询遭系统拒绝，GPU 和可用内存尚未确认。实现前检查实际安装路径及依赖兼容性；速度和 GPU 能力以实测为准。

## 验收

1. 以合成几何验证患者坐标映射、左右方向、斜切截面及不存在结构的隐藏。
2. 在真实 Slicer 中验证模块加载、事件清理、导入、推理失败处理及标签拖动。
3. 在可用脱敏头颈 CT 上运行两个任务，核对分割与 CT 对齐；验证修正不覆盖自动结果。
4. 保存、关闭并重新加载研究包，检查体积、分割、标签偏移及研究记录一致。
5. 用 3–5 个用户病例由用户确认目标结构是否适合研究；记录时间，不设置未经测量的速度承诺。没有真实病例时只能报告软件检查通过，不能宣布模型质量验收完成。
